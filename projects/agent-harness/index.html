01 / Model

The system around the agent.

Agent Harness 关注的不是某个领域业务，而是跨项目重复出现的系统问题：模型如何获得正确上下文，工具如何被发现和执行，失败如何被识别与恢复，Trace 如何记录，以及评测如何把运行行为转化为下一轮工程改进。

02 / Patterns

Patterns carried across projects.

  • 01

    Runtime 与领域能力分离

    通用运行时负责 Agent loop、状态与控制，领域能力通过 Skill/MCP 等机制独立挂载，避免业务逻辑直接进入 Runtime。

  • 02

    Tool contract & orchestration

    统一工具描述、schema、参数合法性、执行结果和失败元数据，让本地工具与 MCP 工具共享一致的调用语义。

  • 03

    Progressive capability exposure

    按任务阶段和领域状态控制模型看到的工具与 Skill，减少工具过载、误选择和不必要调用。

  • 04

    Context Engineering

    将系统提示、历史消息、能力状态、Memory 与压缩上下文作为运行时资源组织，而不是简单拼接完整对话。

  • 05

    Failure recovery

    让错误不只作为字符串返回，而是形成可被 Agent 理解和继续处理的 recovery metadata 与状态。

  • 06

    Trace-level evaluation

    通过完整 Agent 轨迹观察工具选择、参数、恢复和最终结果，将评测从最终答案扩展到执行过程。

Research direction

Agent Harness 的目标是把模型能力转化为稳定软件系统：不仅能完成 Demo，也能够解释失败、约束能力、持续评测，并在复杂业务里逐步迭代。
