01 / Architecture

Business complexity changed the architecture.

Navigation Agent 时代，一个 Agent 可以直接拥有决策与工具循环；进入 GIS 场景后，任务开始包含数据装载、schema 检查、空间运算、图层变换、共享 project state、错误恢复以及最终 Artifact 交付。为避免单个 Agent 同时背负计划、执行和全局控制，GIS Agent 把职责拆成四个清晰角色。

02 / Agent Roles

Four roles, one shared GIS workflow.

A / Planner

Stable task decomposition

把自然语言目标转成有依赖关系的 GIS 计划，并控制当前阶段需要暴露的领域能力；Planner 关注“做什么和先后关系”，不陷入每个工具参数细节。

B / ExecutorFlow

ReAct inside each step

围绕单个计划步骤进行推理、工具选择、Observation 读取和错误恢复，把 QGIS / PostGIS / MLIT 的具体操作落实到可执行状态。

C / Orchestrator

State & control

维护共享任务状态、Agent hand-off、人机交互、重试与恢复，使多个角色在同一个 GIS workspace 中保持一致。

D / Answer

Evidence to delivery

不重新执行分析，只消费已经形成的结果、地图与文件，把执行证据整理成用户可理解的结论与交付物。

为什么不是简单并行：GIS 任务经常连续修改同一个 QGIS project / dataset，后一步依赖前一步 Artifact。因此 Multi-Agent 的价值主要是职责分离与控制，而不是把每一步同时跑起来。

04 / Reliability

Long workflows need recovery, not just reasoning.

历史 Trace 中可以看到真实 GIS 运行会经历 schema 查询、工具失败、人机澄清、重试、session state 读取与继续执行。系统因此把“失败后如何留下可恢复状态”作为 Runtime 能力，而不是让 LLM 只看到一串错误文本。

20+ tool steps复杂 GIS 任务可跨越大量连续工具步骤。
Shared workspaceQGIS project state 与中间 Artifact 必须持续一致。
Human interaction权限、缺失输入或不确定约束需要可控澄清节点。
Schema-aware tools先理解工具与数据 schema，再进行有效调用。
Recovery metadata失败信息被组织为后续动作可消费的状态。
Artifact delivery结果必须落实为可验证的空间数据、地图或文件。
What carried forward

GIS Agent 证明显式角色划分可以控制复杂领域 Workflow；但它也暴露出新的问题——如果每个领域都拥有自己的一套 Planner / Executor / Runtime，系统会重新被业务逻辑绑住。GGAI 因此把这些经验进一步抽象为通用 Runtime、Skill/MCP 和 Harness。

05 / Contribution

Building a controllable GIS multi-agent workflow.

  • 01

    Multi-Agent Runtime 设计

    设计 Planner、ExecutorFlow、Orchestrator、Answer 的 GIS 多步任务框架，并加入 human-interaction 节点；ExecutorFlow 采用 ReAct 范式完成计划步骤的具体执行。

  • 02

    MCP 工具链接入

    接入 QGIS MCP Server 与 MLIT MCP Server，打通桌面 GIS、国土数据查询与 PostgreSQL/PostGIS 空间分析链路。

  • 03

    Skill / Tool 渐进披露

    根据 Planner 当前阶段按需暴露 GIS 能力，减少工具过载和选择错误，提升复杂任务拆解稳定性。

  • 04

    上下文与错误管理

    设计工具调用记录、错误状态、人机交互与恢复机制，使长链路任务在失败后仍然保留可继续执行的状态。

  • 05

    复杂任务执行

    在不微调模型的情况下，通过任务编排、Prompt Engineering 与 Tool Use 支持 20+ 工具步骤的空间分析任务。

  • 06

    Harness 经验沉淀

    把工具可见性控制、MCP 合约、共享状态、失败恢复和 Trace 记录等问题沉淀为后续 GGAI / Agent Harness 的核心设计输入。
