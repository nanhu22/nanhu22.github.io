04 / Ongoing Research · Long-term Agent Memory

Memory
Research

我正在研究长期 Agent Memory 的第三种答案：不在 Semantic / Write-heavy 与 Episodic / Evidence-first 之间简单二选一，而是把原始 Evidence 作为 Source of Truth，把 Semantic、Temporal、Preference、Experience 等 Memory 组织成可重建的 Materialized Views，再通过 Agentic Retrieval 按 Query 动态选择、扩展与验证。

What is the source of truth?

01 / The Split

The real split is the canonical source of truth.

长期 Memory 的分水岭并不是“写入时有没有抽取”，而是系统最终把什么当作不可替代的长期事实来源：是抽取、融合后的结构化 Memory Object，还是原始 episode / conversation / trajectory。这个差异决定了信息损失发生在 Write Path 还是被推迟到 Read Path。

Camp A / Semantic · Write-heavy

Memory object becomes truth.

代表思路包括 Mem0、A-MEM：在写入阶段进行 extraction、dedup、merge、evolution，把 interaction 提前转化为高密度长期知识。

  • Write expensive · Read cheap
  • 语义密度高，适合高频读取
  • 核心风险是 Early Commitment
  • 错误融合与信息丢失通常不可逆
Camp B / Episodic · Evidence-first

Episode remains truth.

代表思路包括 MemPalace、Graphiti：尽量保留原始 episode，把 entity、graph、summary、temporal fact 等视为派生结构或索引。

  • Write cheap / lossless-ish
  • Read intelligent / more expensive
  • 更强的 provenance 与可审计性
  • 核心难点从 extraction 转移到 retrieval
Early Commitment problem

在未来 Query 尚未出现时，系统无法确定当前 interaction 中哪些条件、时间关系和不确定性以后最重要。过早把原始事件压成一句 Memory，可能永久失去未来 Query 所需要的证据。

02 / Third Answer

Evidence is truth. Memory is a set of views.

我当前更关注的方向是 Evidence-first + Multi-view：Raw Episode / Agent Trace 作为 durable evidence，所有高级 Memory 都是带 provenance 的可重建 View。这把 Memory 从“一个统一的 memory object”重新理解成“event log + materialized views + query planner”。

Working thesis

记忆内容尽量晚丢；结构尽量早建；判断尽量在真正知道 Query 后再做。

Evidence Store 保留原始发生过什么；Derived Views 提供未来读取效率；Retrieval Planner 根据 Query 决定访问哪些表示、如何扩展候选并回源验证。

Source
Episode / Trace

消息、工具调用、工具结果、Artifact、时间与 provenance。原则上不让 LLM 改写原始事实。

View 01
Semantic / Fact

从 Evidence 派生出的高密度事实，必须保留 source_episode_ids 与 confidence。

View 02
Temporal / Belief

通过 valid_from / valid_to / supersede 表达事实与信念如何随时间演化，而不是简单覆盖。

View 03

长期稳定但可演化的用户偏好，读取时结合时间与支持证据。

View 04
Experience / Procedure

从 Agent Trace 中形成“做过什么、结果怎样、下次如何做”的经验与程序性记忆。

Planner
Agentic Retrieval

根据 temporal / entity / exact quote / multi-hop / procedural 等 Query 类型规划不同读取路径。

03 / Memory Lifecycle

From extraction to governed memory evolution.

在这个模型里，Extract、Consolidation、Retrieval、Supersede 与 Trace 不是五个孤立模块，而是 Evidence 与 Derived View 之间的生命周期。关键不是“每次都把旧 Memory 改成新 Memory”，而是保留来源、时间有效性和演化关系。

01 / PreserveEvidence

保存 episode、tool result 与 artifact reference。

02 / DeriveExtract

生成 Fact / Preference / Experience 等候选 View。

03 / OrganizeConsolidate

建立关联、去重、证据聚合与 view-level 结构。

04 / EvolveSupersede

通过时间与 provenance 表达旧信念失效或被新证据替代。

05 / UseRetrieve

由 Query Planner 路由索引、展开 evidence、rerank 与 verify。

Trace 的位置：完整 Trace 既是 Experience Memory 的来源，也是 Memory Governance 的审计证据。Memory 的生成、更新和使用都应该能追溯到“为什么会形成这条记忆”。
04 / Retrieval

Retrieval should become query planning, not only Top-K.

复杂长期 Memory 查询往往需要多种表示协作。例如“为什么我最近对项目 A 的态度变了？”不是一次 embedding search 可以解决的：系统需要识别时间问题、找到相关 episode、比较不同时间点的 belief / preference，再回源 Evidence 验证因果线索。

A / Intent

Classify the memory question

Temporal、entity、preference evolution、exact quote、multi-hop 或 procedural。

B / Route

Select views & indexes

Vector、BM25、episode timeline、graph、preference store 与 experience retrieval 按需组合。

C / Expand

Return to evidence

从高层 View 回源关联 episode，补齐时间、上下文和原始措辞。

D / Verify

Assemble an evidence pack

rerank、冲突检测和 provenance 验证后，再把最小充分证据交给 Agent。

05 / Governance

Memory must be reversible and rebuildable.

长期 Agent 最大风险之一不是“忘记”，而是错误 Memory 被后续生成不断强化。因此第三种答案必须把 Governance 作为基础设施：每条 Derived Memory 要能知道来自哪里、何时有效、为何被替代，并能够 rollback / rebuild。

Provenance每个 View 回溯到 source episodes / traces。
Temporal validity事实与信念具有 valid_from / valid_to，而不是永久覆盖。
Confidence区分观察事实、模型推断和弱证据。
Conflict detection新旧证据冲突时保留演化，而不是静默覆盖。
Rebuild派生 View 可从 Evidence Store 重建。
Self-evolution未来进一步学习 Query type → Retrieval Strategy 与 Memory schema。
Current research direction

这仍是我正在研究和验证的方向，而不是已经完成的统一答案。目标是把“记什么”转成三个更基础的问题：保留什么 Evidence、构建哪些 View、在当前 Query 下如何检索与验证它们。
