2026.04 – Present · Design Lead

GGAI · General Geographical Agent

General Agent Runtime · Pluggable Skill/MCP · Trace Eval

构建生产级通用地理信息系统 GGAI，将既有领域能力收敛到“通用单 Agent Runtime + 可插拔 Skill/MCP + Trace Eval”的 Agent Harness。用户可按需启用 QGIS、本地路线规划、OpenStreet、人流分析、灾害分析等领域能力，并将 Sub Agent 作为主 Agent 的工具进行任务派发。

  • Runtime 架构重构：将领域逻辑从 Runtime 下沉到 Skill 与 MCP，保持通用运行时的业务无关性。
  • Context + Tool Orchestrator：参与 QueryEngine、消息构造、历史/Memory/压缩上下文管理，并统一本地工具与 MCP 工具的 schema 校验、执行、失败识别与恢复元数据。
  • Trace Eval 驱动迭代：覆盖任务成功率、工具调用正确率、tool call F1、参数合法性、恢复成功率与最终答案完整性，并通过 LLM-as-Judge 定位工具误判、Skill loop、schema 缺失和领域工具误触发。

2025.08 – 2026.03 · Design Lead

GIS Agent

Planner · ReAct ExecutorFlow · MCP · PostGIS

面向 GIS 场景设计 GIS-Agent，将 QGIS、MCP Server、PostgreSQL/PostGIS 工作流与大模型推理结合，用于灾害预警、土地价格、洪涝风险、人口流动等日本国土数据分析任务。

  • 多步 Agent Runtime：设计 Planner、ExecutorFlow、Orchestrator、Answer 与 human-interaction 节点；ExecutorFlow 采用 ReAct 范式完成分步推理、工具调用、观察读取和错误恢复。
  • MCP + Skill 渐进披露：接入 QGIS MCP Server、MLIT MCP Server 与 PostGIS，并在 Planner 阶段按需暴露工具能力，降低复杂工具集带来的选择错误。
  • 复杂任务执行与 Harness 沉淀：无需模型微调，通过 Prompt Engineering + Tool Use 支持 20+ 工具步骤，并沉淀工具可见性、MCP 合约、失败恢复和 Trace 记录经验。

2024.09 – 2025.08 · Design Lead

Navigation Agent

LangGraph · ReAct · MCP · RAG

面向交通场景设计基于 LangGraph 的 ReAct 单智能体系统，用于路线规划、异常人流分析、交通知识问答与交通态势分析，并通过 Chatbot 提供交互服务。

  • Agent 状态流：基于 LangGraph 设计用户意图识别、任务拆解、工具调用与结果生成流程，并以 ReAct 组织多步骤交通任务。
  • 统一工具闭环：通过 MCP 接入 Google Maps API、FAISS、MySQL 与深度学习预测模型，覆盖路线、知识检索、异常人流与交通预测。
  • 交互与能力沉淀：参与 Gradio 对话式前端，支持地图路线、地图与思维链展示，并沉淀交通领域 Prompt、工具描述与知识检索策略。
